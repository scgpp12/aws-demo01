## 2. 凡例

### 2.1 カバレッジ判定

| 記号 | 定義 |
|---|---|
| ◎ | 単体テスト（UT）と結合テスト（IT）の**両方**で検証されている |
| ◯ | UT または IT の**いずれか一方**で検証されている |
| △ | 設計（BD/DD）には反映されているが、自動テストでの直接検証が無い（構成/コードレビュー範囲） |
| × | テストも設計も無い（未対応） |

### 2.2 結果欄

- **OK** … 対応テストが全て PASS（junit と一致）。
- **制約** … テストは PASS だが、実装挙動・到達性に制約があり申し送りが必要（結果報告書 OBS 参照）。

## 4. 非機能トレーサビリティ（NFR-01〜15）

NFR は IAM・ライフサイクル・暗号化など**自動テストで直接検証できない構成要件**を多く含む。検証方法を正直に区分する。

| NFR-ID | 内容 | 設計対応（BD/該当章） | 検証方法 | 検証状況 |
|---|---|---|---|---|
| NFR-01 | LINE 資格情報を SSM SecureString 保管・プロセス内キャッシュ | IF-05 / BD-08 | 構成レビュー（CDK ssmStmt）＋ 結合テストで SSM をスタブ化し動作前提を確認 | 構成確認済（実 SSM はモック） |
| NFR-02 | webhook 署名検証（HMAC-SHA256、不正は403） | IF-01 / BD-02-2 | 結合テスト（IT-22）で 403/200 を検証 | 検証済（IT-22） |
| NFR-03 | DL 短縮リンク改竄防止（HMAC＋compare_digest） | IF-04 / BD-02-4 | 単体（UT-067,069 署名性質）＋ 結合（IT-20 改竄→404） | 検証済（UT＋IT） |
| NFR-04 | IAM 最小権限（webhook RW / reminder RO、SSM・KMS 限定） | BD-08-1 | 構成レビュー（CDK grant*/ssmStmt/kmsStmt）。テストでは直接検証不可 | 構成レビューで確認 |
| NFR-05 | S3 保護（BPA全ON / SSE / enforceSSL / versioning） | BD-08-3 | 構成レビュー（CDK DataBucket）。結合テスト bucket はバージョニング無効（OBS-03） | 構成レビューで確認（テスト未検証） |
| NFR-06 | フルサーバーレス・従量課金 | BD-01 / BD-02-1 | アーキテクチャ構成レビュー | 構成レビューで確認 |
| NFR-07 | DynamoDB On-Demand（PAY_PER_REQUEST） | BD-01 / BD-02-1 | 構成レビュー（CDK billingMode） | 構成レビューで確認 |
| NFR-08 | webhook 29秒制約・重処理は非同期分離・個別try/except | BD-02-3 / BD-08-4 | 結合テストで非同期 invoke（IT-13）・全体200（IT-22）を間接確認 | 間接確認（IT-13/22） |
| NFR-09 | 標準ライブラリ＋boto3 のみ（外部依存なし） | BD-03 / BD-08-4 | コードレビュー＋ 単体テストが標準ライブラリ生成 xlsx で通る事実で裏付け | コードレビューで確認 |
| NFR-10 | S3 ライフサイクル（managed 60日Archive/365日削除、pending 7日、exports 3日） | BD-08-2 / TBL-05 | 構成レビュー（CDK lifecycleRules）。テストでは直接検証不可 | 構成レビューで確認 |
| NFR-11 | DynamoDB PITR・保存時暗号化 | BD-08-3 / TBL-01〜03 | 構成レビュー（CDK pointInTimeRecovery） | 構成レビューで確認 |
| NFR-12 | 国際化（日本語既定／中国語併記） | BD-08-4 | コードレビュー（i18n.py）。結合テストの応答文言で間接確認 | コードレビューで確認 |
| NFR-13 | TZ（記録UTC／表示JST） | BD-08-4 / TBL-03 | コードレビュー＋ 結合テストで submittedAt 記録を間接確認 | コードレビューで確認 |
| NFR-14 | 削除ポリシー（prod RETAIN / dev DESTROY）・統一タグ | BD-08-3 | 構成レビュー（CDK removalPolicy / Tags） | 構成レビューで確認 |
| NFR-15 | ファイル名互換（ASCII兜底＋RFC5987 UTF-8） | IF-04 | コードレビュー（s3util._disposition）。結合テスト presigned 生成で間接確認 | コードレビューで確認 |

**NFR 検証状況サマリ**：直接テスト検証 = 2件（NFR-02, NFR-03）／ 間接・テストで前提確認 = 3件（NFR-01, NFR-08, NFR-12/13 の一部）／ 構成・コードレビューで確認 = 残り。NFR は性質上テスト不可項目が多く、本番デプロイ前の構成レビュー（CDK 合成結果・実 AWS 設定確認）を申し送りとする（09 報告書 第6章）。

## 6. ギャップ分析

テスト未カバー・設計のみ・制約付きの FR を明示し、リスクと推奨対応を付す。

| GAP-ID | 対象 | 区分 | 内容 | リスク | 推奨対応 |
|---|---|---|---|---|---|
| GAP-01 | FR-26（メニュー）／FR-27（未認識フォールバック） | テスト未カバー（△） | 設計（UI-E07/E08・DD-29）には定義されるが、独立した自動テストケースが UT/IT とも無い。`_route_text` の他ケース実行に付随して通る程度。 | 低。文言返却のみで副作用が無いため品質影響は小。ただしルーティング分岐のデグレ検知ができない。 | E2E（LINE 実機）または `_route_text` 単位の軽量結合ケースを各1件追加。 |
| GAP-02 | FR-25（跨月再提出通知） | 制約付き（◎だが到達性に制約） | 結果は◎（UT-043〜045 ＋ IT-23）だが、結合テスト報告書 OBS-01 のとおり、`_route` 経由の通常提出フローからは実質到達不能。当月提出は `is_late_resubmit=False`、過去月ファイルは年月チェックで弾かれ保存に至らない。IT-23 は `save_submission(period=過去月)` を直接駆動して検証。 | 中。要件 FR-25「過去月補提出時の人事通知」が、通常の利用導線では発火しない設計課題。 | 提出時に対象月を指定できる UI/コマンドを追加し、通常フローから FR-25 を到達可能にする（09 報告書 第4章 OBS-01・第6章申し送り）。 |
| GAP-03 | FR-28（署名検証） | 一部設計のみ（◯） | IT-22 で 403/200 を検証済だが、`line.verify_signature` 本体の単体テストは無い（UT は `_sign_key` のみ）。 | 低。結合テストで実挙動は確認済み。 | 必要なら `verify_signature` の純粋単体ケースを追加（境界：署名欠落・改竄）。 |
| GAP-04 | NFR-04/05/10/11/14（構成系） | 設計のみ（テスト不可） | IAM 最小権限・S3保護・ライフサイクル・PITR・削除ポリシーは自動テストで検証不可。 | 中。設定誤りはテストで検知できず本番で顕在化し得る。 | 本番デプロイ前に `cdk synth` 合成結果のレビュー、または実 AWS での設定棚卸し（構成レビュー）を必須化。 |
| GAP-05 | NFR-05（バージョニング保持） | テスト未検証 | 結合テスト bucket はバージョニング無効（OBS-03）。重複提出時の旧バージョン保持はテスト未検証。 | 低〜中。submissions の再提出判定自体は IT-09/IT-23 で検証済。 | バージョニング有効バケットでの重複提出 E2E を本番前に1件追加。 |
