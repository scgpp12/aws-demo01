## 2. 本書の位置づけ・目的・適用範囲

### 2.1 位置づけ
本書は本システムの要件定義工程の成果物であり、以降の設計・実装・テストの起点となる。

### 2.2 目的
社員が毎月提出する「作業時間記録簿（勤怠）」および「経費（通勤費）」の提出を LINE 上で受け付け、人事担当の提出状況把握・未提出者への督促・一括ダウンロードを効率化する。紙やメール添付による収集・集計・督促の手間を削減することを目的とする。

### 2.3 適用範囲
- 対象：LINE 公式アカウントを介した月次提出物の受付・検証・保管・督促・名簿管理。
- 対象外：Excel 中身の工数・金額の集計、会計システム連携、給与計算（「10. 対象外」参照）。

## 3. 用語定義

| 用語 | 実体 | 説明 |
|---|---|---|
| roster（社員名簿） | DynamoDB `roster` テーブル（PK=`empId`） | 主データ。`empId / name / department / role / lineUserId`。「誰が提出すべきか」を決定する。人事が維持管理する。 |

| kintai（勤怠） | 提出種別の一つ | 作業時間記録簿。表示名「作業時間記録簿」。年月セル B5、氏名セル B3。 |

## 4. 業務概要・登場人物

### 4.1 業務概要
社員は毎月、LINE のトークに Excel ファイル（勤怠・経費）を送信して提出する。システムは種別を自動判定し、年月・氏名を検証して保管する。人事は LINE のコマンドで提出状況を確認し、未提出者へ督促し、当月分を一括ダウンロードする。月末には定時バッチが未提出者へ自動リマインドを送信する。

### 4.2 登場人物（アクター）

| アクター | 説明 |
|---|---|
| 一般社員 | 提出物の送信、テンプレート取得、提出履歴の確認を行う。 |
| 人事担当（HR） | 提出状況一覧、未提出者抽出、催促、一括DL、社員名簿の CRUD を行う。個人提出も可能。 |
| システム（定時バッチ） | EventBridge cron により未提出者へ自動リマインドを送信する（`reminder` Lambda）。 |
| LINE プラットフォーム | webhook 配信、メッセージ送受信、ファイル content API を提供する外部サービス。 |

## 5. 業務フロー

### 5.1 提出フロー
1. 社員が LINE トークに Excel を送信する。
2. システムが未登録ユーザーなら登録フローへ誘導（5.3）。
3. ファイル名から種別を自動判定（kintai/commute）。判定不可なら保留し、種別を質問する。
4. 年月チェック（不一致は保存しない）→ 氏名チェック（勤怠のみ・不一致は保存しない）。
5. S3 へ保存し、submissions に記録、受付メッセージを返信。
6. 休日勤務・日付欠落があれば警告（保存はする）。
7. 跨月の再提出なら人事へ再確認通知をブロードキャスト。

簡易シーケンス:
```
社員 → LINE → Webhook Lambda: ファイル送信
  Webhook → LINE content API: ファイル取得
  Webhook → 種別判定（infer_type）
  Webhook → 年月/氏名チェック（check_file_period / check_name）
  Webhook → S3: put_submission ／ DynamoDB: record_submission
  Webhook → LINE: 受付・警告メッセージ reply
  Webhook → 人事へ resubmit_alert push（跨月再提出時のみ）
```

### 5.2 未提出リマインドフロー
1. EventBridge cron（既定 `cron(0 0 25,28 * ? *)`）が `reminder` Lambda を起動、または人事が「催促」コマンドで非同期 invoke。
2. roster × submissions の差集合で未提出者を算出。
3. LINE 連携済みの未提出者のみ push。未連携者は skip（人事が個別連絡）。

簡易シーケンス:
```
EventBridge → Reminder Lambda（trigger:schedule）
  ｜（または）Webhook → Reminder Lambda 非同期 invoke（trigger:manual）
  Reminder → missing_all_types（差集合算出）
  Reminder → LINE push（連携済の未提出者のみ）／未連携は skip カウント
```

### 5.3 登録（名簿照合）フロー
1. 友だち追加（subscribe）または未登録ユーザーの発言で、氏名入力を要求。
2. 入力氏名を名簿で照合：0 件＝名簿外、複数件＝同姓同名（いずれも人事へ誘導）、1 件＝紐付け（employees.status=active、roster.lineUserId 設定）。

### 5.4 名簿メンテフロー（人事）
1. 人事が「社員追加／社員変更／社員削除／名簿（一覧）」コマンドを送信。
2. システムが roster を更新。
3. 変更（追加/変更/削除）は他の人事へブロードキャスト通知。

## 8. 前提・制約

| ID | 前提・制約 | 根拠 |
|---|---|---|
| PRE-01 | LINE 公式アカウント（Messaging API チャネル）は 1 つ。Webhook ON、自動応答 OFF を推奨。 | `docs/システム要件.md`／`line.py` |

| PRE-05 | リマインド・督促は LINE 連携済みの未提出者のみ配信可能。未連携者は `※Line未登録` 表示で人事が個別連絡。 | `reminder.py:handler`／`line_webhook.py:_mark_unreg` |
| PRE-06 | Bedrock 意図解析は既定 OFF（`BEDROCK_ENABLED=false`）。純キーワードルーティングで動作。 | `config.py:BEDROCK_ENABLED`／`brightstar-hr-stack.ts`（env） |

| PRE-08 | Lambda は Python 3.12 / arm64。コードは標準ライブラリ＋boto3 のみ（ローカル依存インストール不要）。 | `brightstar-hr-stack.ts`（runtime/architecture） |
| PRE-09 | Function URL の認証タイプは NONE（公開）。アクセス制御は LINE 署名検証と HMAC 短縮リンクで担保。 | `brightstar-hr-stack.ts`（FunctionUrlAuthType.NONE） |
| PRE-10 | 提出は毎月「勤怠」「経費」の 2 種別が必須（`SUBMISSION_TYPES`）。 | `config.py:SUBMISSION_TYPES` |
