## 2. テスト方針

### 2.1 結合テストの目的
単体テストが「個々の関数の正しさ」を担保するのに対し、本結合テストは以下を担保する。

1. **ハンドラ跨ぎのフロー**：`line_webhook.handler / _route` → `business` 業務層 → `db / s3util` の連鎖が、要件のシーケンス通りに動くか。
2. **複数リソースの整合**：1 つのイベントが `employees / roster / submissions` の複数テーブルと S3 を同時に正しく更新するか（例：登録で employees.active 化 ＋ roster.lineUserId 設定）。
3. **S3 副作用**：提出物が正しい S3 キーに保存され、年月・氏名不一致時には**保存されない**ことの確認。
4. **分岐フロー**：種別不明→pending 保留→種別語で転正、跨月再提出→人事通知、署名検証 403、短縮リンク改竄 404 など、状態遷移と条件分岐の検証。
5. **非同期連携**：人事「催促」→ reminder Lambda の Event invoke、定時 reminder→未提出者のみ push。

### 2.2 検証範囲（単体との切り分け）
- 単体テスト（`tests/test_business.py` 他）：`normalize_period / infer_type / check_*` 等の純粋・検証ロジックを `make_xlsx` と `monkeypatch` で決定的に検証済み。
- 結合テスト（本書）：上記をモックせず**実コードのまま通し**、テーブル状態・S3 オブジェクト・送信先を assert する。重複は避ける。

## 3. テスト環境

| 項目 | 内容 |
|---|---|
| 言語/ランタイム | Python 3.10（venv：`.venv/Scripts/python.exe`） |
| テストフレームワーク | pytest 9.1.0 |
| AWS モック | **moto 5.2.2**（`mock_aws`）。DynamoDB 3 表 ＋ S3 バケットをメモリ上に構築 |
| 外部 I/O モック | **monkeypatch**：LINE Messaging API（verify_signature / reply / push / download_content）、SSM（line_secret / line_token）、messaging.send、Lambda invoke |
| AWS SDK | boto3 1.43.31 |
| 実行 OS | Windows 11 |

### 3.1 moto バインドの罠への対処（重要）
`common/db.py` は import 時に `boto3.resource("dynamodb")` を、`common/s3util.py` は import 時に `boto3.client("s3")` を生成する。moto はこれらの生成より前に mock を開始しないと効かない。本テストの `tests/integration/conftest.py` は **モジュール読込時（pytest 収集時）** に次の順で初期化する。

1. ダミー資格情報・リソース名（`it-employees` 等）を環境変数へ設定
2. `mock_aws().start()`（セッション全体で有効）
3. boto3 で 3 テーブル（employees: PK `userId` ／ roster: PK `empId` ／ submissions: PK `userId`+SK `sk` ＋ GSI1 `gsi1pk/gsi1sk` ALL）と S3 バケットを作成
4. **その後で** `common.* / handlers.*` を import → 各モジュール内クライアントが moto にバインド

各テスト前（`autouse` フィクスチャ）に 3 テーブルと S3 を全クリアし、テスト間の独立性を確保する。

## 4. テスト構成図（モック境界）

```
   ┌─────────────────────────── テスト対象（実コードで通す）───────────────────────────┐
   │                                                                                   │
   │   handlers/line_webhook.handler / _route / _do_submit / _handle_download          │
   │   handlers/reminder.handler                                                        │
   │        │                                                                           │
   │        ▼                                                                           │
   │   common/business.py（登録・提出・差集合・名簿CRUD）                                 │
   │        │                                                                           │
   │        ▼                                                                           │
   │   common/db.py ──► DynamoDB  ┐                                                     │
   │   common/s3util.py ─► S3      ├─►  ★ moto 5.2.2（メモリ内 AWS）で実リソース挙動    │
   │                              ┘                                                     │
   └───────────────────────────────────────────────────────────────────────────────────┘
            ▲                                   ▲
            │ monkeypatch でスタブ              │ monkeypatch でスタブ
   ┌────────┴───────────┐            ┌──────────┴─────────────┐
   │ common/line.py     │            │ common/config.py        │
   │  verify_signature  │            │  line_secret/line_token │   ← SSM を叩かせない
   │  reply/push        │            └─────────────────────────┘
   │  download_content  │            ┌─────────────────────────┐
   │ common/messaging   │            │ line_webhook._lambda_client│ ← invoke を記録器化
   │  send（宛先記録）  │            └─────────────────────────┘
   └────────────────────┘
```

- **実コードで通す**：HTTP 入口・ルーティング・業務ロジック・DynamoDB/S3 アクセス（moto）。
- **モック**：LINE への実 HTTP（送信内容を `Recorder` に記録して assert）、SSM 取得、Lambda invoke（IT-13 のみ記録器に差替）。
