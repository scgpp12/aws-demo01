## 2. テスト方針

- **実際に動く pytest を書き、実行し、本物の結果（エビデンス）を残す**。数字は junit XML を唯一の真実とし捏造しない。
- 詳細設計の DD-ID を観点に、**境界値・異常系を明示**してケース化する。
- テストを実装の挙動に合わせて歪めない。挙動が要件と矛盾する場合は「指摘事項」として結果報告書に残す。
- 純粋関数中心。AWS / LINE に実アクセスする関数は単体テスト対象外（結合テスト担当範囲）。
- xlsx 入力は **テスト内で最小の xlsx バイト列を自作**（`tests/conftest.py` の `make_xlsx` ヘルパ）して与える。実装と同じ zip+sharedStrings 経路で読めることを保証。
- AWS 依存値（`current_period` / `emp_name` / `line_secret`）は monkeypatch で固定し決定的にする。

## 3. テスト環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11 |
| Python | 3.10.11（専用 venv: `.venv\Scripts\python.exe`） |
| テストフレームワーク | pytest 9.1.0 |
| カバレッジ | pytest-cov（`--cov=common --cov=handlers`） |
| 補助ライブラリ | openpyxl（導入済。ただし本テストの xlsx 生成は標準ライブラリ zip+XML で自作）、moto 5.2.2 / boto3（本テストでは AWS 実呼び出しなし） |
| import 設定 | `tests/conftest.py` で `lambda/` を `sys.path` に追加（`from common import ...` / `from handlers import ...`） |
| AWS 依存 | **なし**。`business` / `xlsx` の import 時に boto3 client/resource が生成されるがネットワーク呼び出しは発生しない。資格情報未設定でも client 生成だけは通るよう `AWS_DEFAULT_REGION` を既定設定。 |
